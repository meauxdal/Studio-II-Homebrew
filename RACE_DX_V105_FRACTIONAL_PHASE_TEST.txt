Race DX v1.05 — fractional-phase intermediate test
2026-09-20

Baseline
--------
The v1.05 source was reconstructed directly by reverse-applying the uploaded
Race_DX_v105_timing_first_pass patch to the uploaded repository. Timestamps were
not used to choose the baseline.

Scope of this build
-------------------
This is intentionally smaller than the failed timing/results pass.

Unchanged from v1.05:
- 65-second initial timer
- +60 seconds per completed road
- whole-second timer decrement logic
- score behavior
- road selection/wrap behavior
- steering, acceleration/braking, collision and road geometry
- countdown behavior and sound effects
- startRace code and address
- graphics/tables/data addresses and raster drawing code

Added:
- RAM $084A: saved encoded race subsecond phase (mRacePhase)
- RAM $084B: phase-valid flag (mRacePhaseValid)
- finishRoad saves the phase at the exact road boundary
- the phase is restored after the final between-road countdown frame, before
  the next VSYNC, so the paused interval consumes no race time

No centisecond/result graphics are present in this build.

Why the failed pass regressed
-----------------------------
The failed pass changed much more than timer storage. It moved 18 existing code
labels, including startRace/globalStateCountDown/finishRoad, introduced remote
branches into countdown and timer-display paths, and rewrote the finish-road
state flow to show results. Those changes altered cycle timing around code that
is known to be beam-sensitive.

The .org $0030 helper itself did NOT overlap VideoInt: the original interrupt
stub ends at $002F. The problem was broader timing/state disturbance, not that
specific overlap hypothesis.

There is also a concrete elapsed-fraction arithmetic bug in the failed pass:
finishRoadStats loads the end phase into D, then executes `ldi <mScratch` before
`sm`, overwriting the end phase before subtraction.

Implementation safety checks
----------------------------
- ASMX build: 0 errors
- Existing labels moved relative to reconstructed v1.05: 0
- New helper code occupies only previously $FF-filled $0430-$0460
- finishRoad's original `REQ / INC rRoadSectorAdr / INC rRoadSectorAdr` three
  bytes are replaced by a same-size LBR hook; the helper performs those exact
  operations before saving phase
- countdownBeepStartDone remains a three-byte LBR; only its target changes
- phase inverse tested across all 60 encoded frame states

Test priorities
---------------
1. Title/author screen is identical to v1.05.
2. Starting lights are identical to v1.05.
3. Start/finish rendering while driving is identical to v1.05.
4. Multiple roads continue indefinitely; no one-road termination.
5. Timer still begins at 65 and awards exactly +60 per road.
6. Between-road pause does not consume the saved fractional phase.
